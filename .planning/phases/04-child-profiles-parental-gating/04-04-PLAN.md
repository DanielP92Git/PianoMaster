<objective>
Teach the four auth-internal services that derive the student id from `supabase.auth.getSession()` to instead accept an explicit `childId` for the target row, while keeping the parent's authenticated session as the RLS principal (RESEARCH.md "auth.uid()-Internal Services"). Under multi-child, the internal `session.user.id` writes to the wrong child (or, for a fresh parent, throws in `award_xp` because the parent's uid ∉ owned_child_ids). This plan makes per-child writes land on the correct child.

Purpose: Pitfall-2/PROFILE-05 correctness — a write must target the active child, not the parent. notificationService was already fixed in Plan 03; this plan covers streak / practiceLog / practiceStreak. The call sites are rescoped in Plans 06/07.
Output: childId-parameterized streak/practiceLog/practiceStreak methods + a new behavioral streakService.test.js + updated service tests.
</objective>
