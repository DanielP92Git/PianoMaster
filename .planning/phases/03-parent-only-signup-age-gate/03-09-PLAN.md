<objective>
Close the single gap from 03-VERIFICATION.md (status: gaps_found, 4.5/5) — WR-01, the OAuth under-18 block-screen race. In `RoleSelection.jsx`, `handleUnder18` currently calls `await logout()` BEFORE `setBlocked(true)`. `logout()` → `supabase.auth.signOut()` → the `SIGNED_OUT` event on App.jsx's `onAuthStateChange` listener (line ~567) → `queryClient.invalidateQueries({ queryKey: ["user"] })` → `getCurrentUser()` resolves to `null` almost synchronously → AuthenticatedWrapper's `if (user && !isLoading && !profile && !userRole)` guard (App.jsx:202) stops matching → RoleSelection (and its local `blocked` state holding AgeBlockScreen) unmounts → ProtectedRoute redirects to `/login`. Result: the under-18 OAuth user is correctly blocked from account creation but may NEVER SEE the friendly guidance, undermining SIGNUP-02's conjunctive "sees guidance AND cannot proceed" for the OAuth entry point.

Fix (verification's 2nd "missing" option — mirrors the proven-reliable email path in SignupForm.jsx, whose `handleUnder18` is a pure `setStep("age-block")`): defer the sign-out until explicit dismissal. `handleUnder18` becomes a pure state update (`setBlocked(true)` only). Because the session stays alive, AuthenticatedWrapper keeps rendering RoleSelection and AgeBlockScreen stays mounted and stable. `await logout()` moves into `handleBackToLogin`, so the sign-out — and the consequent `/login` redirect — happen only when the user explicitly clicks "Back to login", AFTER reading the guidance.
